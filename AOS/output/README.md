# AOS Output — one folder for every AI employee's generated output

Every AI employee's generated reports, feeds and dashboards live here,
one subfolder per employee, named identically to that employee's own
folder under `AOS/` (e.g. `sales-director/runtime/prepare.py` writes
into `output/sales-director/`). Nothing here is founder-edited by hand
— it is all regenerated by the next orchestrator run — with the usual
exception of delivery kits under `output/delivery-intelligence/
delivery-kits/`, which are living documents the founder edits directly
once an engagement starts (see `delivery-intelligence/delivery-
intelligence-engine.md`).

## Layout

- `output/<employee-folder-name>/` — that employee's own dated reports,
  its feed JSON (if it produces one for other employees to read), and
  any employee-specific subfolders (e.g. `output/account-intelligence/
  account-briefs/`, `output/delivery-intelligence/delivery-kits/`)
- `output/orchestrator/` — the Orchestrator's own run artifacts: `logs/`
  (one full run log per run), `reports/` (one Daily Execution Report
  per run), `status.json` (the latest run's completion status)
- `output/daily-briefs/YYYY/MM/DD/` — an immutable dated archive of
  every Daily Executive Brief ever produced

## Why one folder

Before this consolidation (AOS Sprint 24), each employee's output sat
inside its own `<employee>/runtime/output/`, several levels deep in
that employee's own folder tree, alongside its source code and config
— correct for the code that reads it, but not somewhere a human could
browse "what has AOS actually produced" in one place. This folder is
that one place. The code that writes here still lives with each
employee, exactly as before; only where the *output itself* lands
changed.
